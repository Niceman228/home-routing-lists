# Домашняя маршрутизация: подписка Clash и zapret2

**Актуальная схема с 27.10.2026:** прокси и правила берутся из полной Clash-подписки, включая `DIRECT`. Sing-box сохраняет перехват LAN и блокировку рекламы, Mihomo выбирает маршрут по подписке, zapret2 обрабатывает внешние TCP/TLS-соединения VPN. Прежняя политика «всё через VPN» отменена по выбору владельца.

- [Настройка, проверки и эксплуатация](docs/router-setup.md)
- [Результаты восьмичасового подбора zapret2](docs/zapret-tuning-2026-10-27.md)
- [Исходники интеграции подписки](router/home-clash/README.md)

В репозитории нет действующей подписки, реквизитов прокси, адресов VPN-серверов, приватных конфигов и резервных копий. Исходники интеграции рассчитаны на существующую локальную схему, а не на установку на произвольный роутер одной командой.

## Прежние списки и генератор

Раздел ниже описывает прежнюю схему и сохранённый генератор списков. Генератор продолжает собирать `dist/`, но эти списки **больше не выбирают пользовательский маршрут на текущем роутере**. Они не заменяют правила полной подписки.

Правила для трёх маршрутов: `direct`, `proxy` (VLESS) и `zapret`.
Здесь нет VPN-подписки, адресов серверов, паролей и конфигурации домашнего роутера.

## Что редактировать

`lists/direct.txt`, `lists/proxy.txt`, `lists/zapret.txt`: по одному домену на строку.
Домен включает поддомены. Комментарии начинаются с `#`.

`rules.json`: готовые сервисные категории и правила регионов. Например:

```json
"regions": [
  {"match": {"domain_suffix": ["ru", "рф", "su"]}, "route": "direct"},
  {"match": {"geoip": ["RU", "BY", "KZ"]}, "route": "direct"},
  {"match": {"geoip": ["US"]}, "route": "proxy"}
]
```

Это пример, а не текущая политика. Зоны доменов ставятся перед GeoIP; правила внутри каждого блока проверяются сверху вниз. GeoIP определяется по адресу назначения, а не по языку, владельцу сайта или месту пользователя. Общие CDN могут обслуживать сайты разных стран.

Приоритет: собственный DIRECT → собственный VLESS → собственный ZAPRET → сервисные категории в порядке файла → доменные зоны → GeoIP → `default`.
Например, `blocked.ru` в `lists/proxy.txt` пойдёт через VLESS, даже если `.ru` или GeoIP RU направлены напрямую.
Исключение `safe.example.com` не удаляет правило для остальных поддоменов `example.com`.

**Сейчас `default: proxy`.** Неизвестные назначения идут через VLESS, кроме явных DIRECT-исключений, доменных зон .ru/.рф и GeoIP RU. Сервисные VLESS-исключения сохраняют приоритет над региональными DIRECT-правилами.
Перехват IPv4 охватывает внешний TCP/UDP; окончательный маршрут выбирается по исключениям и регионам. При остановке ядра пересылка блокируется, а не выпускается напрямую. Для возврата к выборочному профилю поставь `default: direct`.

**YouTube и Discord HTTPS/Gateway направляются в zapret по перенесённым d8-профилям OpenWrt.** YouTube QUIC использует UDP/443 только у youtube.com, googlevideo.com, ytimg.com. Discord voice/UDP, другие порты и неизвестные назначения — VLESS с прежними DIRECT-исключениями. UDP-очередь роутера увеличена до 20 исходящих / 10 ответных пакетов согласно пакету переноса. Для добавления новых zapret-доменов нужен соответствующий установленный профиль; один список метод обхода не создаёт. Авторизованные чаты и звонки не подтверждены публичными пробами.

`zapret_ready` не заменяет проверку метода на роутере. Добавление домена в zapret-list не добавляет метод обхода: роутер допускает прямой zapret только для доменов установленных профилей. Остальные записи идут через VLESS до установки и проверки подходящего профиля. Для регионов используй direct/proxy; GeoIP → zapret не поддерживается.

## Обновление

GitHub Actions собирает `dist/bundle.json` после изменения исходных правил и ежедневно около **01:20 МСК**. Роутер скачивает готовый файл ежедневно в **04:07 МСК**.
Успешный запуск Actions виден во вкладке Actions. Если сборка завершилась ошибкой, рабочий bundle остаётся прежним.
`dist/` генерируется автоматически: редактируй исходные списки и `rules.json`.
Роутер получает только JSON-данные и не исполняет скачанный код. В bundle входят отдельные наборы proxy-маршрутов, DNS и эффективных zapret-условий. Вложенные отрицания сохраняют приоритет исключений; удалять домены из сгенерированных условий вручную нельзя.
Одна загрузка bundle исключает смешивание файлов из разных коммитов. Последняя рабочая версия остаётся в локальном кеше роутера при ошибке загрузки.

Источники сервисов: [itdoginfo/allow-domains](https://github.com/itdoginfo/allow-domains).
GeoIP: [MetaCubeX/meta-rules-dat](https://github.com/MetaCubeX/meta-rules-dat), ветка `meta`, `geo/geoip/XX.list`.
URL и SHA256 каждой использованной версии сохраняются в `dist/sources.json`.
Широкие записи национальных зон из сервисных списков игнорируются: такие правила добавляются явно в `regions`.
Полные сети CDN/хостингов в выбранные сервисные категории не добавляются автоматически.
Публичные изменения правил видны всем; не помещай сюда личные внутренние домены.

## Проверка локально

```sh
python -m unittest discover -s tests -v
python tools/build.py
```

Текущая реализация GeoIP и перехвата рассчитана на IPv4. IPv6-пересылка из домашней LAN отключена отдельно на роутере.
Приложения с собственным DNS/DoH и соединениями без узнаваемого домена могут обходить доменную классификацию при `default: direct`; для них нужен GeoIP/IP-профиль или `default: proxy` и отдельная проверка приложения.
