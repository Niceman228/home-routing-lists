# Текущая настройка роутера — 27 октября 2026

## Результат

На OpenWrt настроено получение полной Clash-подписки: 14 профилей, одна пользовательская группа выбора, 203 правила и внешний rule-provider. Выбран ранее проверенный Arcturus, VLESS поверх gRPC/TLS. Не все профили подписки обязаны быть доступны; успешный разбор конфигурации не означает успешного подключения к каждому узлу.

Проверенная платформа: CMCC RAX3000M, ARM64/mediatek-filogic, около512МиБ RAM, OpenWrt25.12.6, ядро Linux6.12.112. Адреса домашней сети и серверов не нужны для повторного понимания архитектуры и здесь не публикуются.

По выбору владельца часть направлений идёт `DIRECT`, остальные — через выбранный прокси. Прежний режим «всё через VPN» больше не является текущей политикой.

## Путь трафика

```text
Домашнее устройство
  → существующий IPv4 TCP/UDP TPROXY OpenWrt
  → sing-box: DNS-перехват, определение доменов, adblock
  → локальный SOCKS Mihomo
  → правила подписки
       ├─ DIRECT → WAN
       └─ группа прокси → выбранный VPN → WAN
                              ↑
                   zapret2 на внешнем TCP/TLS
```

Sing-box не переводит правила Clash в собственный формат: решения принимает Mihomo. Это сохраняет поддерживаемые им типы прокси, порядок правил и внешние rule-provider. Старые списки Podkop не управляют пользовательским маршрутом. Итоговый локальный hook применяется после исходного генератора Podkop, поэтому его reload не должен возвращать прежнюю политику.

Параметры текущей интеграции:

| Назначение | Значение |
|---|---|
| Ядро маршрутизации по подписке | Mihomo 1.19.32, ARM64 |
| Существующий перехват | sing-box 1.13.21 |
| SOCKS Mihomo | `127.0.0.1:11082` |
| DNS Mihomo | `127.0.0.1:1053` |
| API Mihomo | `127.0.0.1:19090`, с локальным секретом |

DNS сохраняет настройки подписки с локальными изменениями listen/FakeIP для совместимости двух ядер. Adblock сохранён. Прямой IPv6 forward домашних устройств остаётся запрещённым. Существующий guard прямой IPv4-пересылки не мешает `DIRECT`: такие соединения открывает сам Mihomo после локального перехвата.

### Ограничения

- Роутер не видит имена приложений на домашних устройствах. `PROCESS-NAME` и `PROCESS-NAME-WILDCARD` загружены вместе с подпиской, но поиск процессов отключён; соответствующие приложения на клиентах этими правилами не определяются.
- Переход через локальный SOCKS скрывает исходный LAN-IP от Mihomo. Если будущая подписка добавит правила по исходному адресу устройства, их потребуется проверить отдельно.
- Это IPv4-схема, а не настройка полноценного клиентского IPv6 через VPN.
- Сбой отдельного сайта при работающем VPN не доказывает DPI-блокировку внешнего VPN. Для GitHub таймауты наблюдались и без обработки zapret.

## VPN и zapret2

Zapret2 v1.0.5.2 обрабатывает внешнее TCP/TLS-соединение VPN, а не расшифрованное содержимое туннеля. Установлена стратегия `fake` с `tcp_md5`, затем `multisplit` на позициях `1,midsld`. Файл TLS ClientHello берётся из установленного zapret2, а его содержимое не публикуется вместе с пользовательскими конфигами.

NFQUEUE301 ограничена адресами и портами VPN-endpoint, socket mark и внешним интерфейсом. IPv4 endpoint добавляются из подписки; старые адреса сохраняются для существующих соединений. Диапазон TCP-фильтра позволяет использовать разные серверные порты, сохраняя узкое ограничение endpoint. Изначальная NFQUEUE300 не удалялась.

**Эта TCP-стратегия не обрабатывает Hysteria2/UDP.** Обработка внешнего TCP/TLS подтверждена, дополнительное преимущество против ТСПУ при работающем контрольном соединении не доказано. [Подробные результаты подбора](zapret-tuning-2026-10-27.md).

## Управление подпиской

В LuCI: **Сервисы → Подписка Clash**. Путь страницы: `/cgi-bin/luci/admin/services/home-clash`.

1. Вставить HTTPS-ссылку подписки в поле и нажать «Импортировать / обновить».
2. Без новой ссылки кнопка обновляет текущую подписку.
3. В группе подписки выбрать прокси и нажать «Выбрать».

Нужно использовать эту страницу, а не прежний импорт ссылок VLESS в Podkop. Один сервер подписки может отдавать разные форматы разным клиентам: в проверенной подписке User-Agent Mihomo/FlClash получает полный YAML, а v2rayNG/sing-box — только URI узлов. Предыдущий импортёр поэтому не получал правила.

Обновление по cron: **01:17, 07:17, 13:17, 19:17 МСК**. Внешний rule-provider обновляется ядром по интервалу подписки. Публикация этого репозитория не заменяет подписку и не запускает скачанный shell-код на роутере.

Команды администратора:

```sh
/usr/sbin/home-clash status
/usr/sbin/home-clash update
/usr/sbin/home-clash health
/usr/sbin/home-clash select 'ИМЯ ГРУППЫ' 'ИМЯ ПРОКСИ'
```

При обновлении загружается кандидат, проверяется Linux-парсером и подключением. Если прежний выбранный профиль остаётся доступным, выбор сохраняется. При неуспехе выбора проверяются альтернативы. Если кандидат не удаётся применить, восстанавливается прежний конфиг. Ссылка меняется только после успешного импорта.

## Сохранение и восстановление

Подписка, исходный YAML, выбранные профили и API-секрет находятся в root-only `/etc/home-clash/private`. Их нельзя добавлять в Git, отчёты или публичные журналы.

Рабочие файлы и сжатое ядро добавлены в локальный `sysupgrade.conf`. Ядро распаковывается в `/tmp/home-clash/mihomo` при старте. После установки было свободно около14МиБ overlay и230МиБ доступной RAM; несжатый57МиБ бинарник не следует копировать в overlay.

Перед переключением сохранена закрытая резервная копия изменяемых файлов на роутере и ноутбуке. Router-local procd-таймер на900сек мог восстановить прежнюю схему без SSH. После успешных проверок откат отключён. Новые изменения маршрутизации также следует делать с отдельной резервной копией и независимым откатом.

Восстановление из этой конкретной копии требует вернуть прежний hook, конфиг sing-box, sync/API/status-скрипты, init/rules zapret и `sysupgrade.conf`, перезапустить sing-box и рабочий DPI, затем отключить Mihomo. Нельзя запускать старые экспериментальные rollback-скрипты как универсальное восстановление: они могли сохранять другую историческую схему.
